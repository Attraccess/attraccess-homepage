# Attraccess homepage hero film — "Closed Loop"

A 52-second seamless loop for the attraccess.org hero. One unbroken camera move across the flow
editor's canvas follows a single card tap at an Attractap reader as it becomes a checked introduction,
a live session, a flow that switches power and unlocks the workstation, a bill, scheduled maintenance
and finally a resource that is ready again. The view then widens to show the whole loop around the
logo, with the integrations that plug into it, and returns to the reader where it started.

The film exists in **English and German**. Both share timing, layout and camera; each shows its own
demo instance captured in its own UI language ("North Campus Prototyping Lab" / "Prototyping-Labor
Nordcampus"), with localized captions, node titles (the app's exact UI strings) and integration labels.
The Attractap reader screens are the genuine German firmware screens in both versions — the firmware
has no English locale.

Creative direction: `docs/creative-brief.md`. Verified product facts and claim boundaries:
`docs/research/feature-inventory.md`. Capture provenance: `docs/captures.md`, `assets/reader/README.md`.

All web files are silent (no audio track). Both cuts share one timeline, so the embed can switch
between them at the same timecode when the viewport crosses the breakpoint.

## Embed

`preview/index.html` is the reference implementation. In short:

- `<video muted playsinline loop>` with no `autoplay` attribute; a small script picks the first source
  the browser can play (AV1 → VP9 → H.264; Safari/iOS try H.264 first because WebKit can show stale AV1 frames after a seek) for the current orientation (`max-width: 640px` → 4:5
  portrait cut) and starts playback only when `prefers-reduced-motion` is not set.
- Reduced motion: the video is hidden and the `<picture>` poster (AVIF/WebP/JPG) is shown instead.
- A visible pause/play button (WCAG 2.2.2), pausing when off-screen or when the tab is hidden.
- The poster is always underneath, so there is no blank frame while the video loads.

## Editing the film

Media under `apps/hero-film` is stored in Git LFS (`git lfs install` once, then `git lfs pull`).
Dependencies come from the repo's pnpm workspace (`pnpm install` at the repo root).

```sh
pnpm film:studio               # from the repo root: Remotion Studio (scrub, inspect, tweak)
cd apps/hero-film/film
./scripts/export.sh            # render all four masters (EN/DE × landscape/portrait), encode web files + posters, copy to preview/media
LOCALES=de ./scripts/export.sh # one language only
SKIP_RENDER=1 ./scripts/export.sh   # re-encode only (tune AV1_CRF / VP9_CRF / H264_CRF)
```

Per language, rendering both cuts takes about 3 minutes on an 8-core Mac; encoding about 8 more.
After changing `preview/index.html`, run `node preview/build-de.mjs` to regenerate the German page.

`out/` and `preview/media/` are build output and stay out of git. To ship a new cut, copy the web files
into the site: `cp out/web/* ../web/public/hero-film/`.

## Recapturing product screens

The capture tools in `tools/` drive a real Attraccess instance. They expect a bootstrapped checkout
of github.com/Attraccess/Attraccess at `apps/hero-film/software` (gitignored), either a worktree or a
symlink, at the commit the captures were taken from:

```sh
git -C <path-to-Attraccess> worktree add "$PWD/apps/hero-film/software" a4d5e3b772686164dc353f2449edf0617a3509f5
```

The German demo uses its own checkout at `tools/demo/de/.runtime/software`. Commands and the capture
log are in `docs/captures.md`.

| File | Role |
|------|------|
| `src/timeline.ts` | **Start here.** Beat table (hold times + camera framing), pulse/wire timing, captions |
| `src/layout.ts` | World positions of every node (1 world unit = 1 CSS px of product UI) |
| `src/shots.ts` | Which capture region appears in which node, per locale; reader screen language |
| `src/i18n.ts` | All on-screen copy per locale: captions, node titles, integration labels, card |
| `src/Film.tsx` | Assembles nodes, wires, reader, logo |
| `src/Extensions.tsx` | Integration chips on the outer ring |
| `src/Captions.tsx` | Beat captions (screen space) |
| `src/components/` | Camera-aware primitives: `Node`, `Wire`, `Reader`, `Crop`, `Seq`, `Swap`, `FlowPulses`, `Grid`, `Logo` |
| `src/flowEdges.ts` | Generated from `assets/captures/flow2-coordinates.json` |

Pacing: each screen holds for 3–5 s with only a slow push-in; the camera travels between holds in
about 1.5 s while the pulse runs along the connecting wire. To lengthen or shorten a beat, edit its
`hold` in `BEATS`; camera keys, wire timings and captions are derived from it.

## Authenticity notes

- Every product screen is a real capture of the current software (commit `a4d5e3b7`) running against
  a dedicated demo database ("North Campus Prototyping Lab") with simulated hardware. Nothing is
  redrawn; motion comes from camera moves, pulses, crossfades between real states and real frame
  sequences.
- The Attractap screens are genuine LVGL renders of the production firmware screens. The firmware
  ships German copy only, so the film shows the untouched German screens
  (`READER_LANG` in `src/shots.ts` switches to capture-only English label substitutions).
- The Attractap enclosure is the repository's CAD render; the mascot and wordmark come from the app's
  brand assets (wordmark path generated from `libs/ui/src/AttraccessLogo.tsx`).
- Node titles use exact UI vocabulary ("Usage started", "Send HTTP request", "Unlock PC", "Report
  meter", "Usage stopped"). Captions stay within verified behaviour: no booking, offline, safety or
  compliance claims.
- The session timer's first frames in the captured start sequence briefly show `-1:-1:-1` (a real
  frontend glitch right after a session starts); those frames are skipped in the film.
